Foundations

The ISM Code and the ISPS Code are usually introduced together because both represent the same kind of regulatory move: instead of specifying a technical requirement for the ship itself, each requires the operating company to establish a documented process — a safety management system for ISM, a security plan for ISPS — and to demonstrate it is actually being followed, not just written down.

Both were adopted as amendments to SOLAS rather than as freestanding conventions, both apply primarily at the level of the operating company (not just the individual ship), and both were direct responses to failures that pure technical/construction rules hadn't prevented: management-process failure for ISM, deliberate hostile acts for ISPS.

Anyone needing to understand how modern maritime regulation reaches beyond steel and equipment into how a company actually manages risk day to day — a distinct regulatory layer from the technical conventions in the companion reference page.

SOLAS, MARPOL, and STCW set technical construction, pollution, and competence standards. ISM and ISPS instead regulate management process and security behavior — a company can meet every technical requirement in the other three conventions and still fail an ISM or ISPS audit if its documented procedures aren't actually followed in practice.

Core Structure

Document of Compliance (DOC)
Issued to the operating company, confirming it maintains an approved Safety Management System across its fleet.
ISMShip
Safety Management Certificate (SMC)
Issued to each vessel, confirming it operates under the company's approved SMS.
ISPSPlan
Ship / Port Facility Security Plan
An approved plan detailing security measures for the specific vessel or port facility.
ISPSLevels
Security Levels 1–3
A three-tier system (normal, heightened, exceptional) determining which access-control measures are actually in force.

Going Deeper

Written procedures for safety and environmental protection, defined responsibilities and authority levels, emergency preparedness procedures, a system for reporting non-conformities and near-misses, and a documented process for internal audits and management review — the SMS is meant to be a living system, continuously improved, not a binder written once and shelved.

A company earns a DOC by demonstrating its overall SMS meets the ISM Code; each individual vessel it operates then earns its own SMC by demonstrating it operates under that approved SMS. Losing the company's DOC effectively invalidates every one of its vessels' SMCs, which is exactly the kind of company-wide accountability the ISM Code was designed to create.

Security Level 1 is the normal, default operating condition with baseline measures always in force. Security Level 2 applies during a period of heightened risk, adding measures such as increased access screening. Security Level 3 applies when a specific incident is imminent or has occurred, requiring the most restrictive measures. A port facility's security level can require every ship calling there to match it, regardless of the ship's own assessed risk.

A Company Security Officer (CSO) oversees security across a fleet, a Ship Security Officer (SSO) is responsible for a specific vessel's security plan and its implementation, and a Port Facility Security Officer (PFSO) holds the equivalent responsibility ashore for a specific port facility — three distinct roles that must coordinate whenever a ship calls at a port.

Definitions & Scope

ISM Code

The code requiring shipping companies to maintain a documented Safety Management System, made mandatory under SOLAS in 1998.

Safety Management System (SMS)

A company's documented procedures, responsibilities, and continuous-improvement process for safety and environmental protection.

Document of Compliance (DOC)

A certificate issued to a company confirming its SMS meets ISM Code requirements.

ISPS Code

The code requiring ship and port security plans against deliberate, hostile acts, made mandatory under SOLAS in 2004.

Security Level

A three-tier ISPS classification (1-3) determining which security measures are in force at a given time.

Ship Security Officer (SSO)

The individual responsible for a specific vessel's security plan and its day-to-day implementation.

Classroom Uses

Officer Role Matching Drill

Learners match CSO, SSO, and PFSO to their scope of responsibility (fleet, ship, or port facility).

Security Level Scenario

Given a hypothetical heightened-risk scenario, learners identify what a Security Level 2 designation would plausibly require.

DOC/SMC Accountability Case

Learners reason through what happens to a company's fleet if its DOC is suspended, testing the company/ship certificate relationship.

ISM vs. ISPS Sorting Drill

Given ten described requirements, learners sort each as ISM (management process) or ISPS (security), reinforcing Section 3's distinction.
